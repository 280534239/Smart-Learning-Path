# 用户中心设计方案

> 日期：2026-11-05
> 状态：方案稿（尚未实施）
> 范围：为「智学路径」新增用户中心，含入口、功能模块与分期优先级。

---

## 一、现状盘点

用户中心能放什么，取决于当前已有能力与数据结构。以下为与用户中心直接相关的现状。

### 1. 导航与入口

- `frontend/src/components/AppLayout.vue` 顶栏右侧已有「头像 + 用户名」区块（`user-summary`），当前为纯展示、不可点击。
- 顶栏同时存在主题切换按钮与退出按钮。
- 侧边栏当前分组：
  - 学习中心：学习看板 / 智能诊断 / 知识图谱 / 学习路径 / 在线练习
  - 辅助工具：AI 答疑 / 错题本
- 尚无「用户中心」页面或入口。

### 2. 账号数据（`app/models/user.py`）

`User` 模型字段较少：

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `username` | 登录用户名，唯一 |
| `email` | 邮箱，唯一 |
| `password_hash` | 密码哈希 |
| `avatar_url` | 头像地址，可空 |
| `created_at` | 注册时间 |

缺失：昵称、个人简介、手机号、学习目标/水平、偏好设置等。

### 3. 已有认证接口（`app/routers/auth.py`）

- `POST /register` 注册
- `POST /login` 登录
- `GET /profile` 获取当前用户信息

缺失：修改资料、修改密码、修改邮箱、注销账号、退出所有设备。

### 4. 可聚合的学习数据

以下模型均可按用户聚合，供用户中心统计使用：

- `learning_records` —— 学习行为记录（learn / practice / diagnosis，含时长、前后掌握度）
- `attempt_records` —— 答题记录（正确率、用时、错误类型）
- `error_book` —— 错题本（是否已掌握、复习次数）
- `initial_diagnoses` —— 初始诊断（学习目标、水平、状态、结果）
- `learning_paths` —— AI 学习路径
- `chat_sessions` —— AI 答疑会话历史
- `diagnosis_snapshots` —— 历次诊断掌握度快照
- `user_learning_contents` —— 用户与学习内容的归属关系

### 5. 现有功能差异点

- `Dashboard` 是**单科目**进度看板（带 `subject` 参数）；用户中心适合做**跨科目/全局**统计，二者互补、不冲突。
- 已有 `subject_deletion_service`（删除某学习内容及其全部关联数据），数据管理模块可复用。
- 主题切换（浅色/深色）已在 `user` store 中本地持久化，可直接搬入用户中心设置。

## 二、入口设计

1. 将顶栏 `user-summary` 改为**可点击**，点击展开下拉菜单：个人中心 / 我的资料 / 账号设置 / 退出。
2. 在侧边栏底部（或顶部）新增「用户中心」入口，路由 `/user-center`。
3. 页面采用左侧 tab 布局，模块划分：
   - 个人资料
   - 学习档案
   - 成就
   - 设置
   - 账号安全
   - 数据管理

视觉风格复用现有 `el-card` / `surface-panel` / `el-menu` 体系，保持与 Dashboard、AppLayout 一致。

## 三、功能模块

### A. 个人资料（Profile）

| 条目 | 说明 | 现状 |
|---|---|---|
| 头像 | 上传/更换头像（本地或对象存储） | 字段已有，无上传能力 |
| 昵称 | 展示名，与登录用户名分离 | 需新增字段 |
| 用户名 | 只读展示 | 已有 |
| 邮箱 | 展示 + 修改 + 验证 | 只读，可加修改/验证 |
| 个人简介 | 一句话签名，可选 | 需新增字段 |
| 学习目标 / 当前水平 | 与初始诊断的 `learning_goal` / `level` 打通展示 | 数据已有，散落在诊断中 |
| 注册时间 / 加入天数 | 展示 | 已有 `created_at` |

### B. 学习档案 / 全局统计（跨科目）

区别于单科目的 Dashboard，全局统计汇总所有学习内容：

- 总学习时长、总做题数、整体正确率、连续学习天数（跨科目汇总）。
- 各学习内容掌握度一览（`user_learning_contents` + 各自 `overall_mastery`）。
- 历史诊断记录列表（`diagnosis_snapshots`：初始诊断 + 智能诊断，含时间、得分、模块掌握度）。
- 已生成的学习路径列表。
- 错题总数（`error_book`）、AI 答疑会话数（`chat_sessions`）。
- 学习日历（可将 Dashboard 日历升级为全局，或置于个人档案内）。

### C. 成就 / 勋章（Achievements，可选进阶）

基于已有数据做规则化成就，例如：

- 首刷错题 / 错题清零
- 连续打卡 N 天
- 正确率达标
- 完成首个学习路径
- 累计做题 100 / 500 道

> 需新增 `achievements` 表及触发逻辑，增量较大，建议二期。

### D. 设置与偏好（Preferences）

- 主题（浅色/深色）—— 已有，直接搬入。
- 默认学习内容（记住上次选择的 `activeSubject`）。
- 每日学习目标（如每天 N 道题 / N 分钟，可配合提醒）。
- 错题本复习提醒开关、通知偏好。
- 语言 / 界面密度等（可选）。

### E. 账号安全（Security）

- 修改密码（校验旧密码 + `hash_password`，`security.py` 已具备能力）。
- 修改邮箱（复用注册中的唯一性校验）。
- 退出登录 / 退出所有设备（当前退出仅清 localStorage，可升级为 token 失效）。
- 注销账号（删除用户 + 级联删除全部数据；`User` 关系已配置 `cascade="all, delete-orphan"`，后端可做，但需二次确认）。

### F. 数据管理 / 隐私（Data Management）

- 我的学习内容列表 + 单个删除（复用 `subject_deletion_service`）。
- 导出个人数据（JSON：档案 + 学习记录 + 错题 + 诊断）。
- 清空某一科目的学习记录 / 错题（建议提供「只清记录、保留图谱」的细分）。

### G. 消息 / 通知（Notifications，可选）

- 站内通知：每日学习提醒、AI 生成完成、诊断完成等。
- 需新增表 + 各触发点埋点。

## 四、优先级分期

### 一期（MVP，快速落地、闭环价值高）

1. 个人资料展示 + 编辑（昵称、头像、简介）。
2. 修改密码。
3. 全局学习统计页（跨科目汇总 + 各科目掌握一览 + 历史诊断列表）—— 复用现有查询，成本低、观感好。
4. 设置页：主题 + 默认学习内容。

### 二期

5. 邮箱修改 + 验证。
6. 注销账号 + 退出所有设备。
7. 数据导出 / 单科数据清理。
8. 成就与勋章。

### 三期（可选）

9. 站内通知。
10. 每日学习目标 + 打卡提醒。

## 五、涉及改动概览（实施时参考）

| 层 | 改动点 |
|---|---|
| 数据模型 | `User` 增加昵称/简介等字段；可选新增 `achievements`、`notifications` 表 |
| 后端路由 | 新增 `user_center` 路由（资料编辑、改密码、全局统计、数据导出/清理等） |
| 后端服务 | 新增聚合统计服务；复用 `adaptive_engine`、`subject_deletion_service` |
| 前端页面 | 新增 `UserCenter.vue`（tab 布局）及子模块组件 |
| 前端路由 | 新增 `/user-center` 路由与入口 |
| 前端 store | 扩展 `user` store（昵称、头像、偏好） |
| 入口 | `AppLayout.vue` 顶栏 `user-summary` 可点击 + 侧边栏入口 |

## 六、待确认问题

- 头像上传方案：本地静态目录 / 对象存储 / 仅支持外链 URL？
- 邮箱验证：是否需要验证码 / 邮件服务，还是仅做格式与唯一性校验？
- 注销账号与数据删除：是否需要「冷静期」或软删除（先停用再物理删除）？
- 数据导出格式：JSON 仅作 MVP，还是需要 CSV/PDF？
- 每日学习目标与提醒：是否需要推送（浏览器通知 / 邮件），还是仅站内展示？
